# 架构与数据流

## 整体结构

```
┌─────────────┐        ┌──────────────┐        ┌─────────────┐
│   QQ 用户    │ ◄────► │   NapCat      │ ◄────► │   AstrBot   │
└─────────────┘        │  (协议端)      │  ws    │  (逻辑层)    │
                       └──────────────┘        └──────┬──────┘
                                                      │
                        ┌─────────────────────────────┼──────────────────┐
                        │                             │                  │
                  ┌─────▼─────┐              ┌────────▼───────┐   ┌──────▼──────┐
                  │  LLM 供应商 │              │  各功能插件     │   │  TTS 服务   │
                  └───────────┘              └────────┬───────┘   └─────────────┘
                                                      │
                                       ┌──────────────┼──────────────┐
                                       │              │              │
                                 ┌─────▼────┐   ┌─────▼────┐   ┌─────▼─────┐
                                 │ 本地 agent │   │ 音色训练  │   │ VOCALOID  │
                                 │ (自己电脑) │   │ (RVC/DDSP)│   │  (自己电脑)│
                                 └──────────┘   └──────────┘   └───────────┘
```

- **服务器**：跑 AstrBot、插件、记忆、定时任务
- **本地电脑**：跑 agent（键鼠控制）、TTS、VOCALOID、音色训练
- 两者之间通过 SSH 反向隧道互通，agent 只监听 127.0.0.1

## 一次普通对话

1. QQ 消息 → NapCat → AstrBot（`aiocqhttp` 适配器）
2. `on_llm_request` 钩子：记忆插件检索相关事实，拼进 system prompt
3. LLM 生成回复
4. `on_llm_response` 钩子：记忆插件把这一轮攒进 buffer，满 8 轮抽一次事实
5. 回复发回 NapCat → QQ

## 一次写歌

1. LLM 按约定格式生成歌词（分节 + 假名）
2. `song_builder.py` 按和弦骨架生成旋律，写 `song.yaml`
3. 组装 `.vpr`（VOCALOID 工程，本质是 ZIP + `sequence.json`）
4. `vpr_phonemes.py` 直接把音素写进 `sequence.json`（绕过 GUI）
5. 通过 agent 驱动 VOCALOID 打开工程、导出音频
6. 导出的音频回传到服务器，转 mp3 发回 QQ

## 一次翻唱

1. 原曲 → Demucs 分离出人声与伴奏
2. 人声重采样到 48k
3. RVC 模型把音色转成目标角色
4. 与伴奏混合，导出成品

## 记忆的数据流

```
对话 ──每 8 轮──► LLM 抽取事实 ──► facts.jsonl
                                    │
每次提问 ──► 关键词匹配 + 重要性 × 时间衰减 ──► 注入 system prompt
                                    │
                            定期清理低价值记忆（>3 天且 <0.12）
```

设计取舍：
- **纯文本 JSONL**：可读、可手工编辑、不依赖数据库
- **关键词检索**：不需要嵌入模型，零额外成本
- 代价是换种说法就找不到，后续可以升级为向量检索
